# Forma: пилот главного тренера и силового специалиста

Три настоящих последовательных API-вызова: главный формулирует задачу → силовой специалист v1.1 готовит заключение → главный v1.0 проверяет и отвечает. Это фиксированный процесс координации двух ролей, а не связь с существующими чатами ChatGPT. Остальные специалисты пока не подключены.

## Запуск

1. Развернуть `supabase/functions/forma-coach` в проекте Forma. `verify_jwt=false` нужен для новой конфигурации ключей; функция сама проверяет пользовательский JWT через Auth до чтения данных и ИИ-вызовов.
2. В серверных Secrets задать `OPENAI_API_KEY`, `COACH_MODEL` (доступная вашему API-аккаунту модель), `COACH_ALLOWED_USER_IDS` (UUID тестовых пользователей через запятую), `COACH_ALLOWED_ORIGINS` (точные origin веб-версии/Capacitor, без пути и завершающего `/`). `SUPABASE_URL` предоставляется средой. Используется `SUPABASE_ANON_KEY` либо явно заданный `COACH_SUPABASE_PUBLISHABLE_KEY`.
3. Собрать фронтенд с `VITE_FORMA_COACH_ENABLED=true`. По умолчанию интерфейс выключен. Ни OpenAI-ключ, ни service-role ключ не должны попадать в Vite-переменные.
4. Войти под разрешённым тестовым пользователем, открыть зал, заполнить сведения и вопрос, подтвердить передачу данных. Проверить ответ и реальные `trace` в ответе функции. Вызов не меняет планы или занятия.

Секреты вводятся только в защищённых настройках серверной среды. API оплачивается отдельно от ChatGPT; до запуска установить бюджет и лимиты в API-аккаунте. Не выводить секреты или пользовательские данные в логи.

## Данные и ограничения

- Читаются до 30 подтверждённых занятий текущего пользователя с пользовательским JWT и фильтром `user_id`. RLS не обходится; service-role ключ не используется.
- Поля: дата, тип, дистанция, длительность, группа мышц, основные и дополнительные строки упражнений. Маршруты GPS, email и данные участников не передаются.
- Дополнительный профиль пользователь вводит явно, в этом пилоте он не хранится. Личный профиль Василия не встроен в публичный репозиторий.
- В старых строках Forma подходы агрегированы. Отдельные веса каждого сета, RIR, сон и боль могут отсутствовать. Агенту запрещено их выдумывать; требуется последующее развитие журнала подходов.
- Нет внешнего научного поиска, анализа видео, долговременной памяти диалога и автоматической записи программ. Реестр источников — справочный, а не подтверждение поиска в текущем запросе.
- Три вызова ограничены токенами и общим таймаутом. Отказ или незавершённый ответ одного этапа останавливает процесс; непроверенное заключение не выдаётся как финальный ответ.
- Защита повторных запросов действует только внутри одного прогретого экземпляра функции. Перед публичной подпиской нужны распределённые квоты, бюджет на пользователя, сохранение версий профиля, журнал и независимая оценка рекомендаций.
- `store:false` отключает хранение Responses для последующего получения; это не обещание нулевого хранения данных провайдером.

## Проверка

`node --test tests/coach.test.mjs` проверяет процесс на имитированных ответах: вход, изоляцию по user_id, согласие, отключённую конфигурацию, сбой специалиста и порядок трёх вызовов. Реальный ответ ИИ и деплой проверяются отдельно после настройки серверных секретов. `npm run build` проверяет сборку интерфейса.
