## 1. Проект и хранение данных

- React 19 + Vite + Capacitor, GitHub `4uvakinvv-hue/fit-tracker`; Supabase проект `osxxmmutwehabkvylkki`.
- Данные пользователей хранятся в Supabase, включая `profiles`, `sessions`, `gym_templates`, `coach_workout_plans`, `coach_memberships`, `plans`, `daily_steps`, `expedition_days`.
- Отправлять результаты тренировки в `sessions` только после подтверждения; незавершённый черновик тренировки от тренера хранится локально и восстанавливается при возврате. Не терять черновик при ошибке записи.
- У записей тренировок важны `user_id`, `date`, `type`, `confirmed`, `base_rows`, `extra_rows`, `coach_plan_id` и `rating_eligible`. Существующие JSONB-записи не перезаписывать без необходимости; история не должна изменяться из-за обновления профиля.
- Авторизацию и доступ в админку проверять сервером/RLS, а не только отображением кнопок.
- Никогда не считать демонстрационные данные результатом пользователя. Не смешивать план, черновик и подтверждённый факт.

## 2. Баллы и рейтинг — действующая логика

Источник реализации: `src/App.jsx`: `isRatingSession`, `ratingActiveDates`, `streakState`, `pointEvents`, `gpsBonusForSession`, `stepPoints`.

1. Активный день: **+5**, максимум один базовый бонус за календарный день, даже если было несколько тренировок.
2. Достаточное число шагов для самостоятельного активного дня — **15 000+**. Для сессий ходьбы в квалификации истории есть отдельный порог **10 000** шагов; не путать эти условия.
3. Последовательные активные дни создают серию до шести дней: второй день **+1** дополнительно, третий **+2**, четвёртый **+3**, пятый **+4**, шестой **+5**. После шести дней серия закрывается; седьмой — день восстановления: активность может дать базовые +5, но не продлевает шестидневную серию.
4. После трёх дней без активности начинает действовать штраф **−1 за следующий день**; спортивная составляющая рейтинга не уходит ниже нуля.
5. Завершённая задним числом тренировка может попасть в историю/статистику, но без рейтингового начисления, если `rating_eligible=false`.
6. Подтверждённая GPS-велопоездка **строго более 100 км** со средней скоростью **не выше 50 км/ч** даёт дополнительный **+5**. Не начислять за недостоверные GPS-метрики.
7. Подсчёт рейтинга опирается на подтверждённые подходящие сессии и `daily_steps`/проверенные дни экспедиции. Запись сама по себе не равна праву на рейтинг.
8. Отдельный персональный модуль штрафов за вредную привычку не должен менять формулу спортивного рейтинга остальных пользователей.

## 3. Тоннаж — контракт вычисления (новое правило релиза)

Тоннаж — стандартизированный показатель объёма силовой работы в **кг**. Для обычных упражнений:

```
тоннаж_подхода = рабочий_вес × фактические_повторения
тоннаж_упражнения = Σ тоннаж_подхода
тоннаж_тренировки = Σ тоннаж_упражнения
```

Если интерфейс хранит одинаковые повторы и вес для всех подходов: `вес × повторы × количество_подходов`. Если подходы различаются, использовать фактические данные каждого подхода по отдельности. Для гантелей с `weightBasis='per_hand'` множитель 2, если это пара гантелей, а не одностороннее движение. Пустое или невалидное значение нельзя интерпретировать как выполненную нагрузку.

**Специальные случаи:**

| Упражнение | Что вводится в поле «Вес» | Нагрузка одного повторения |
|---|---|---|
| Подтягивания | Дополнительное отягощение, 0 кг без него | Собственный вес + отягощение |
| Отжимания на брусьях | Дополнительное отягощение, 0 кг без него | Собственный вес + отягощение |
| Гравитрон (подтягивания/брусья) | Вес помощи/противовеса, кг | max(0, собственный вес − помощь) |
| Обычное упражнение | Рабочий вес, кг | Рабочий вес, с учётом `weightBasis` |

Примеры: при массе тела 100 кг на гравитроне помощь 25 кг означает 75 кг на повторение; 10 повторений = 750 кг тоннажа. При подтягиваниях с +20 кг и массой 90 кг — 110 кг на повторение; 3×8 = 2640 кг.

- Сохранять массу тела пользователя в `profiles.body_weight_kg` (кг, числовое поле); менять только через узко ограниченную RPC `set_body_weight_kg(p_weight)` с проверкой `auth.uid()`, чтобы пользователь не получил права редактировать баллы, имя и чужие профили.
- В карточке **только** подтягиваний, брусьев и гравитрона показать компактное поле «Собственный вес, кг»: автоматически подставлять профиль, если он заполнен, иначе запрашивать число.
- Для гравитрона поле отягощения подписывать **«Помощь, кг»**, для подтягиваний и брусьев **«Отягощение, кг»**.
- В момент записи тренировки сохранять использованную массу тела в результатах: изменения профиля впоследствии **не пересчитывают историю**.
- Над списком упражнений тренировки от тренера вывести **компактный общий тоннаж**. При любом изменении веса, количества подходов или повторений пересчитывать немедленно.
- Плановый и фактический тоннаж различать. Пока сессия не подтверждена, не называть план выполненной работой.
- Если масса тела отсутствует, не выдавать условный расчёт без массы за полный тоннаж; просить указать её.
- Эти правила — **учёт объёма**, а не утверждение о точной физической работе/биомеханических силах на каждом участке амплитуды.
- Код нового расчёта: `src/coach-volume.js`. Следующий шаг для точного учёта: по-подходное сохранение, если текущая схема ещё хранит только средние повторения.

## 4. Тренерские принципы

- План строится с учётом предыдущих результатов и прогрессии нагрузки; тяжёлые дни — меньше повторений и больше рабочие веса, чем в соответствующих облегчённых тренировках, если техника и безопасность позволяют.
- **Лёгкий день:** без отказа, с запасом повторений.
- **Средний день:** **технический отказ** — прекратить подход, когда следующее повторение уже потребовало бы нарушения техники.
- **Тяжёлый день:** **полный отказ** — невозможность самостоятельно завершить следующее повторение при заданной нагрузке. Это не разрешение терять контроль над весом; обеспечить безопасный способ завершить подход.
- Пользователь тренируется без партнёра; учитываются риски работы до отказа со свободными весами. Дроп-сеты и ограниченный контролируемый читинг могут обсуждаться для подходящих упражнений, но не как универсальная обязанность и не вместо безопасной техники.

### 4.1. Методика, утверждённая владельцем (30.10–03.11.2026)

Порядок работы ИИ-тренера и контракт плана — `docs/AI_COACH.md`. Личные правила конкретного человека — только в `private.coach_program_rules`, не в репозитории.

- **Цикл:** 3 недели = 9 тренировок, сплит из трёх дней; блоки идут лёгкий → средний → тяжёлый, по 3 тренировки. Фазу продвигает только сохранённая тренировка.
- **Лёгкий блок:** отказа нет нигде, запас 2–3 повтора, больше повторов и меньше вес, без дропов и читинга, подходы сверх плана не добавлять — смысл в разгрузке. Новые упражнения вводить здесь.
- **Средний блок:** технический отказ там, где он назначен.
- **Тяжёлый блок:** меньше повторов и больше вес. Полный отказ — только в последнем подходе подходящей изоляции (тренажёр, блок, гантели в безопасной позиции). В свободных жимах (штанга, гантели, жим стоя) и в жиме ногами — без отказа, остановка с запасом 1–2 повтора, потому что человек тренируется один. Дроп-сет — не больше одного на тренировку, в последнем подходе изоляции на блоке или тренажёре, одно снижение на 20–25 %, без планового отдыха. Читинг не назначать без оценки техники.
- **Подходы:** минимум 3 рабочих на упражнение, никогда 2; разминка отдельно; RIR человек не записывает.
- **Повторы по блокам** (согласовано 07.11.2026): базовые упражнения (жимы, тяги, выпады) — тяжёлый 6–8, средний 8–10, лёгкий 10–12; изоляция (махи, задняя дельта, руки, разгибания и сгибания ног, ягодичный мост, сведения, икры) — тяжёлый 8–10, средний 10–12, лёгкий 12–15. Упражнения, где работает позвоночник (гиперэкстензия, скручивания), — всегда 12–15. Мелкие мышцы в 6–8 повторах — это раскачка и нагрузка на суставы, поэтому у изоляции шкала выше. Сам диапазон на рост влияет мало; его задача — разнообразие стимула и управление усталостью.
- **Не больше 8 упражнений в тренировке** (согласовано 07.11.2026): последние упражнения длинного дня выполняются плохо или пропускаются.
- **Прогрессия:** сравнивать только сопоставимое — то же упражнение, тот же тренажёр, тот же тип блока; тяжёлый блок — с тяжёлым блоком прошлого цикла. Рабочее правило: дошёл до верха диапазона чисто — следующая ступень веса, иначе +1 повтор. Это настраиваемая тренерская эвристика, не научный закон. Быстрый рост весов после перерыва — возврат силы, а не рост мышц.
- **Приоритетные мышцы:** добавочный объём в другие дни набирается **другим упражнением с другим профилем нагрузки** (например, махи гантелями в одном дне и махи в блоке или тренажёре в другом), а не повтором того же упражнения.
- **Состав дня** закреплён на цикл: от блока к блоку меняются веса, повторы и отказ. **Базовые упражнения** не меняются и между циклами, по ним меряется прогресс; при смене приоритетов меняются только добавочные.
- **Веса:** не выдумывать для новых упражнений и тренажёров — `weight: null`, «подобрать на разминке». Не пересчитывать вес между разными тренажёрами, между гантелями и блоком.
- **Суперсеты:** для изоляции и мышц-антагонистов (бицепс + трицепс, махи + разгибание рук и т. п.); не с тяжёлыми базовыми упражнениями. Разметка — поле `superset` (§5).
- **План и факт:** если человек стабильно делает больше подходов, чем в плане, план приводится к реальному объёму, а человека просят не добавлять сверх плана; в лёгком блоке — не добавлять вовсе.
- **Боль и травма:** движение прекращается; автоматический план не публикуется; нужна проверка тренером.
- **Общение:** прямо и честно, без похвалы и смягчений; факты из данных отделять от предположений.
- Короткая плашка в карточке: только «Технический отказ» или «Полный отказ» и «Подробнее». **Никакого** переключателя «лёгкий/средний/тяжёлый» в самой плашке. Тип определяет тренерская методика/план.
- Текст «Подробнее» — профессиональное короткое пояснение разницы между мышечным и техническим отказом; без длинной инструкции на основном экране.

## 5. Интерфейс тренировки от тренера

- Порядок верхней части экрана фиксирован: заголовок «Тренировка от тренера», сворачиваемые общие рекомендации, название назначенной тренировки, компактный показатель «Тоннаж тренировки: … кг», затем карточки упражнений. Общий тоннаж не дублировать внутри карточек упражнений.
- Пользовательское поле выбора даты на этом экране отсутствует. При подтверждении результата приложение автоматически записывает текущую московскую календарную дату. План, локальный черновик и исторические сессии остаются отдельными сущностями: скрытие поля даты не завершает назначение, не меняет историю и не удаляет сохранённый черновик.
- Карточка должна оставаться компактной. Под названием упражнения **мелким одинаковым шрифтом** выводить строку плана и до **трёх последних фактически выполненных** результатов этого упражнения в столбик, новые сверху (решение владельца 03.11.2026). Одна сессия даёт не больше одной строки; совпадение по названию упражнения без учёта регистра и пробелов по краям. Если результат один — подпись «Прошлая:», если больше — «Прошлые:». Код: `recentResultsByExercise` в `src/coach-presentation.js`.
- Формат: `План: 3 × 6–10 · 85 кг` / `Прошлые: 30.10 (пт) (T) · 3 × 7 · 90 кг · Комментарий пользователя` и ниже ещё до двух записей. День недели автоматически считать из даты реальной записи; не выдумывать.
- **Следующий релиз (решение владельца 07.11.2026; пока не реализовано):** в каждой из трёх последних фактически выполненных записей **конкретного упражнения** после даты и дня недели добавлять отдельную метку в скобках: `(L)` — лёгкий блок, `(S)` — средний блок, `(T)` — тяжёлый блок. Тип нагрузки брать из сохранённой метаинформации **той предыдущей тренировки**, а не из текущего назначенного блока. Если исторический блок определить достоверно нельзя, не проставлять букву наугад.
- Если у подходящего исторического выполнения есть **комментарий пользователя**, выводить его **в той же строке после веса**, например: `21.10 (ср) (S) · 3 × 8 · 80 кг · Последний подход дался тяжело`. Если комментария нет, строка заканчивается весом. Не подменять комментарий пользователя заметками ИИ-тренера или текстом техники. На узком экране допускается перенос длинного комментария внутри компактной области строки без перекрытия соседних элементов.
- Три строки — это три **последних фактических выполнения данного упражнения**, а не три упражнения или три календарных дня вообще. Если подходящих записей только две, показывать две; если одну — одну. Сохранять сортировку от новой к старой, обновлять после сохранения занятия.
- **Примагничивание при прокрутке** (решение владельца 03.11.2026): на экране тренировки от тренера карточка упражнения мягко встаёт к верху экрана (отступ 10 px), когда прокрутка останавливается рядом с ней, — чтобы уставшими руками не приходилось точно доводить экран. Только `scroll-snap-type: y proximity`, не `mandatory`: свободная прокрутка, длинные раскрытые карточки, верх экрана и кнопка «Сохранить» остаются доступны. Код: блок scroll-snap в конце `src/styles.css`.
- **Суперсет** (решение владельца 03.11.2026): два и более **подряд идущих** упражнения плана с одинаковым полем `superset` (`"A"`, `"B"`…). На каждой карточке значок «Суперсет A · 1/2», карточки визуально связаны. Вместо строки отдыха у всех, кроме последнего, выводится «Без отдыха → упражнение N»; отдых после пары тренер пишет в `comment` последнего упражнения. Одинокая метка или метки, разорванные другим упражнением, суперсетом не считаются. Суперсеты — для изоляции и антагонистов, не для тяжёлых базовых. Код: `supersetGroup` в `src/coach-presentation.js`.
- Техника не дублируется между открытой карточкой и выпадающим блоком. Основной экран — только факты и управление подходами/повторами/весом.
- Выпадающий раздел «Техника и нюансы» по умолчанию закрыт. Внутри: что это за конкретное упражнение, базовая техника, ошибки/нюансы; персональные указания тренера выделить отдельно. Методическое описание упражнения хранить отдельно от рекомендаций ИИ в стандартизированной библиотеке `src/exercise-technique.js` (что это за упражнение, выполнение, нюансы). При добавлении нового упражнения расширять библиотеку и покрывать тестом.
- История: показывать **реально выполненные цифры**; скрывать пояснения техники и длинные инструкции. Сохранить комментарии пользователя, если они действительно нужны как заметки о результате.

## 6. Профиль и установка приложения

- На главном экране — компактный визуально кликабельный элемент аккаунта с аватаром, именем и индикатором перехода в «Мой профиль». Он участвует в обычной компоновке шапки, сокращает длинное имя многоточием и не размещается абсолютным или фиксированным слоем поверх логотипа, уведомлений либо карточки баллов. **Не** добавлять пожелания доброго утра и определение часового пояса для приветствий (владелец прямо отменил эту идею).
- В профиле: имя, зарегистрированные контакты, смена пароля, масса тела, будущий раздел управления подписками; админка только для администратора.
- Раздел «О приложении» использовать для инструкций по установке Android (APK) и iPhone (Safari/PWA), версии и необходимой справки. Не показывать там редактор имени/админку.
- Изменение имени сохраняет действующие ограничения существующего RPC (`change_profile_name`, не чаще раза в 24 часа).

## 7. Геолокация и режим фланирования

- Фланирование — активность без заранее выбранного маршрута/способа перемещения, возможны пешие участки и транспорт; связь может отсутствовать. Записывать сессии устойчиво к офлайну и возобновлению.

Выбранный вариант использовать как тип/контекст конкретной сессии для подписи и анализа активности, не подменяя его обычным режимом запланированной прогулки или мотопоездки. Оба варианта сохраняют идею фланирования — выезд/выход без заранее заданного маршрута и плана; сохраняются действующие правила GPS, офлайна, остановок, защиты от глушения/спуфинга, статистики и восстановления записи. Новое правило меняет только выбор вида фланирования; прочие утверждённые правила режима не отменяются.
- GPS-скачки, увод в море, глушение/подмена сигнала, а также авиарежим **не должны превращать 15 км в 200 км или выдавать скорости 180 км/ч на велосипеде**.
- Геометрический фильтр, разрывы, проверка разумных скоростей и качество GPS — отдельные проверки; не считать расстояние прыжка через большой разрыв действительным. Исходные точки сохранять с признаками недоверия для диагностики.
- Код: `src/gps-protection.js`, `src/flaneuring.js` и интеграция с `src/App.jsx`.
