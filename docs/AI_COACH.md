# ИИ-тренер Forma — порядок работы

> Для любого ИИ или человека, который составляет тренировки в Forma. Читать после `AGENTS.md`. Методика тренинга — `docs/COACH_KNOWLEDGE.md`, интерфейс экрана — `docs/FORMA_PRODUCT_RULES.md` §5. Обновлено: 2026-11-03.
>
> **Репозиторий публичный.** Личные данные, цели, история и правила конкретного человека здесь не пишутся — только в базе, в `private.coach_program_rules`.

## 1. Где что лежит

| Данные | Где | Примечание |
|---|---|---|
| Выполненные тренировки | `public.sessions` (`type='gym'`, `confirmed=true`) | `base_rows` — по упражнению: `exercise`, `sets`, `reps` (среднее), `weight`, `comment`, `weightBasis`, `superset`, плановые `target*`/`coachNote`. `coach_plan_id` — по какому плану. `coach_feedback` — поле «Пожелания к следующей тренировке». |
| Назначенные планы | `public.coach_workout_plans` | Неизменяемые. `status`: `published` / `archived`. Приложение показывает **последний `published` по `created_at`**; `scheduled_date` — только ориентир. `source_session_id` уникален. |
| Постоянные правила человека | `private.coach_program_rules` | Один текстовый документ на пользователя: цикл, приоритеты, раскладка дней, предпочтения, личные цели. Только сервер, приложение не видит. Схема: `supabase/coach-program-rules.sql`. |
| Настройки автоалгоритма | `private.coach_load_preferences` | `target_sets`, `use_rir`, `auto_progress`. |
| Доступ к тренеру | `public.coach_memberships` | Без активного доступа план в приложении не показывается. |
| Анкета новичка | `public.coach_intakes` | Первый план генерирует триггер, см. `TRAINER_SETUP.md`. |
| Масса тела | `public.profiles.body_weight_kg` | Нужна для тоннажа подтягиваний, брусьев, гравитрона. |

## 2. Кто пишет планы

- **Владелец (основной аккаунт).** Планы пишет тренер вручную — сейчас ИИ-тренер через подключение к базе. Автопубликация для этого аккаунта **отключена** условием триггера `trg_forma_autopublish_coach_plan` (`WHEN … user_id <> <owner>`, см. `supabase/coach-autopublish-trigger.sql`). Если после сохранённой тренировки план не написан, приложение продолжит показывать уже выполненный план с пометкой «Тренировка уже сохранена».
- **Остальные участники с доступом.** После сохранения триггер публикует консервативный следующий план (`supabase/coach-next-plan.sql`): те же упражнения, +1 повтор или примерно +2,5 % веса у вершины диапазона, при словах о боли/травме план не публикуется.

## 3. Порядок работы — каждый раз

1. **Правила человека.** Прочитать `private.coach_program_rules`. Это главный источник: цикл, текущая фаза, приоритеты, состав дней, договорённости.
2. **Факт.** Прочитать последние сессии минимум за полный цикл, **включая `comment` каждого упражнения и `coach_feedback`**. Комментарии — источник замен («делал стоя», «это был другой тренажёр»), ощущений и пожеланий.
3. **Текущий план.** Прочитать последний опубликованный план и его `notes`, определить фазу. Фазу продвигает только сохранённая тренировка, не календарь.
4. **Разбор факта против плана.** Подходы сверх плана, замены упражнений и тренажёров, пирамиды (в поле веса — основной рабочий), читинг, отказ. Не сравнивать разные тренажёры и варианты упражнения; если вес из одного источника противоречит комментарию — не угадывать, оставить поле веса пустым и попросить вписать.
5. **Составить план** по методике (`COACH_KNOWLEDGE.md`: §1 видение владельца, §3 женская методика, если применимо) и правилам человека.
6. **Опубликовать** новой строкой `insert` в `coach_workout_plans`. Никогда не редактировать опубликованный план и не писать в `sessions`. Если заменяется ещё не начатый план — перевести старый в `archived`, только если по нему нет сохранённой сессии. Помнить: черновик, уже начатый на телефоне, держится за свой план.
7. **Проверить** запросом как в приложении (последний `published` по `created_at` для пользователя): вернулся новый план, число упражнений и подходов верное.
8. **Записать решения.** Каждое новое решение человека — в `private.coach_program_rules` в тот же день. Общие методические правила, утверждённые владельцем, — в `COACH_KNOWLEDGE.md` §1.
9. **Ответ человеку.** Прямо и честно, без похвалы и смягчений. Факты из данных отделять от предположений. Не выдумывать веса, причины и «научные» пороги.

Нельзя публиковать план «наперёд» через одну тренировку: он сразу заменит ближайший на экране. Будущие дни — описать в `notes` или в правилах, опубликовать в свою очередь.

## 4. Контракт плана

Строка `coach_workout_plans`:

- `title` — «<День> · <лёгкий | средний | тяжёлый> блок · n/3». **Слово блока обязательно**: по нему приложение выбирает плашку отказа (`failureType` в `src/coach-volume.js`): лёгкий — никогда, средний — «Технический отказ», тяжёлый — «Полный отказ» у упражнений с `trainToFailure: true`.
- `scheduled_date` — ориентир даты, `status` — `published`, `source_session_id` — сессия, после которой написан план (или `null`, если от этой сессии уже есть план).
- `notes` — начинаются с маркера `[<АВТОР>_COACH source=<session_id>]`, затем: фаза цикла, разбор прошлой тренировки, правила этого дня, отдых, что делать при боли, договорённости на следующие дни. В приложении — свёрнутая кнопка «Общие рекомендации от тренера».

Упражнение в `exercises` (от 1 до 30):

| Поле | Тип | Смысл |
|---|---|---|
| `exercise` | строка | Для продолжения истории — **точно то же название**, что в прошлых сессиях: строки «Прошлые» ищутся по названию без учёта регистра. Новое упражнение — по возможности название из `src/exercise-catalog.js`. |
| `sets` | целое ≥ 3 | Рабочие подходы, разминка отдельно. |
| `reps` | строка | Диапазон, например `"8–12"`. |
| `startReps` | целое | Что подставить в поле повторов. |
| `weight` | число или `null` | `null` = «вес подобрать»; человек обязан вписать вес перед сохранением. Не выдумывать. |
| `weightBasis` | `"per_hand"` | Вес на одну руку (гантели, односторонние движения). |
| `trainToFailure` | bool | Отказ в последнем подходе (вид — по блоку в `title`). |
| `superset` | строка | `"A"`, `"B"`… на двух и более **подряд идущих** упражнениях. Отдых после пары — в `comment` последнего. |
| `comment` | строка | Указания тренера: прошлый факт, логика нагрузки, техника, отдых. Показывается под «Техника и нюансы»; первая фраза, начинающаяся с «Отдых …», выводится на карточке. |

`targetRir` не назначать аккаунтам с `use_rir=false`.

## 5. Подключение другого ИИ

- Нужен доступ к базе Supabase проекта: коннектор Supabase от владельца или серверная среда с service role. Ключи — никогда в клиенте, в репозитории или в чате.
- Минимум операций: чтение `sessions`, `coach_workout_plans`, `profiles.body_weight_kg`, `private.coach_program_rules`; `insert` в `coach_workout_plans`; смена `status` на `archived`; обновление `private.coach_program_rules`.
- Изменения схемы базы — только с явного разрешения владельца, с SQL-файлом в `supabase/` в том же коммите.
- Изменения кода — по `AGENTS.md`: от свежего `main`, тесты, сборка, обновление документации в том же коммите, публикация с проверкой головы ветки. Публикация в `main` сама собирает веб (GitHub Pages, архив Sprinthost) и Android APK (релиз `android-current`).
- Отдельный рантайм ассистента (операции `forma_trainer_request` / `forma_trainer_publish`, см. `GYM_TRAINER_SETUP.md`) подчиняется тем же правилам.
